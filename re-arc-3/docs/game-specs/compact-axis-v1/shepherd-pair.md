Shepherd Pair

This is a game about escorting a companion becoming difficult because every instruction must be generated by walking a different maze.

Authored campaign: exactly 7 levels.

The player controls the blue shepherd in the left enclosure. Whenever the shepherd successfully moves one logical cell, the yellow companion in the right enclosure attempts the same directional move. Each character resolves walls and one-way gates in its own enclosure, so their positions gradually diverge.

The companion’s green pen is the sole objective. The shepherd has no destination. Its enclosure is instead a physical command generator: a direction can be transmitted only when the shepherd itself can legally move that way.

General rules
Objective

A level succeeds exactly when, after resolving a directional action, the companion occupies the single green pen cell in the companion enclosure.

Relevant to validation:

companion_pos == goal_pos is the entire success predicate.

The shepherd may finish anywhere.

Gate history, step count, transient flashes, and the path taken are ignored.

Companion and shepherd revisits are allowed.

Bumping walls or gates is allowed.

There is no terminal failure state.

Once the companion enters the pen, won is latched and subsequent actions do nothing.

The companion never begins on the pen in an authored level.

Action space

The environment accepts the specified action space exactly:

UP

DOWN

LEFT

RIGHT

SPACE

CLICK(x,y) for any rendered cell

Only the four directional actions change puzzle positions.

SPACE and every click are inert in all seven levels. They do not select anything, trigger anything, or advance a timer. No object displays a click highlight or hover response. Clicking is deliberately absent because direct manipulation would bypass the game’s central constraint: commands must be generated by shepherd movement.

For every level:

selected_object = null

cursor_visible = false

there are no clickable hit regions

there is no energy meter, timer, or action cap

the host may reset the episode externally, but reset is not an in-game action

Logical movement lattice

Each enclosure is an independent 8-row × 7-column logical board.

Coordinates are local to an enclosure:

rows 1…8, top to bottom

columns 1…7, left to right

positions are written (row, column)

one directional action changes the shepherd by exactly one logical cell when legal

The two characters never collide because they occupy different enclosures.

Walls

A character may occupy only an authored floor cell.

A movement into any of the following is blocked:

a wall cell

outside the 8×7 logical board

the forbidden direction of a one-way gate

Walls and outer boundaries use the same collision rule.

One-way gates

A gate is stored as an ordered pair of adjacent floor cells:

source → destination

Movement from source to destination is legal. Movement from destination back to source is blocked.

A gate has no dynamic state:

it never opens, closes, toggles, or disappears

crossing it does not consume it

a character may cross it forward more than once after returning by another route

all consequences arise from geometry, not crossing history

A gate affects only its own enclosure.

Exact transition order

For a directional action d:

Clear the previous directional feedback.

Compute the shepherd’s proposed adjacent cell.

Test that movement against the shepherd enclosure.

If the shepherd movement is blocked:

neither position changes;

the companion does not attempt anything;

no command tracer appears;

the struck wall or reverse-facing gate flashes.

If the shepherd movement is legal:

record the shepherd’s new position;

from the companion’s pre-step position, test the same direction in the companion enclosure;

move the companion if legal, otherwise leave it in place;

commit the two resulting positions;

test the companion position against the pen.

Thus a blocked shepherd action is not a wait command. It produces no companion instruction.

Reference pseudocode:

Python
Run
def step(action):
    if state.won:
        return

    if action == SPACE or action.is_click:
        return

    direction = action.direction
    old_s = state.shepherd_pos
    old_c = state.companion_pos

    new_s, shepherd_moved, s_obstruction = try_move(
        shepherd_board, old_s, direction
    )

    if not shepherd_moved:
        state.feedback = ShepherdBlocked(
            direction=direction,
            obstruction=s_obstruction,
        )
        return

    new_c, companion_moved, c_obstruction = try_move(
        companion_board, old_c, direction
    )

    state.shepherd_pos = new_s
    state.companion_pos = new_c

    if companion_moved:
        state.feedback = SharedMove(direction=direction)
    else:
        state.feedback = CompanionBlocked(
            direction=direction,
            obstruction=c_obstruction,
        )

    if new_c == level.goal_pos:
        state.won = True

Movement across an edge is implemented as:

Python
Run
def edge_is_legal(board, p, q):
    if q not in board.floor_cells:
        return False

    gate = board.gate_on_undirected_edge(p, q)

    if gate is None:
        return True

    return gate.source == p and gate.destination == q
Rendering contract
Canvas and board placement

The rendered canvas is exactly 64×64 pixels.

Pixel coordinates are zero-indexed.

Canvas background: color 5

Left enclosure cell origin: (x=1, y=16)

Right enclosure cell origin: (x=35, y=16)

Logical cell size: 4×4 pixels

Logical cell (r,c) occupies:

x = origin_x + 4(c−1) … origin_x + 4(c−1) + 3
y = origin_y + 4(r−1) … origin_y + 4(r−1) + 3

The left enclosure therefore occupies pixels x=1…28, y=16…47.
The right enclosure occupies x=35…62, y=16…47.

A one-pixel outer enclosure frame uses color 3:

left frame bounds: x=0…29, y=15…48

right frame bounds: x=34…63, y=15…48

There are no internal cell borders or grid lines. Contiguous floor and wall cells render as contiguous regions.

Pen

The pen is the twelve-pixel perimeter of its 4×4 cell in color 14. The inner 2×2 area remains floor color 1.

The companion is drawn above the pen, leaving parts of the green perimeter visible while occupied.

Gate arrow

A gate is drawn across the shared edge of its two cells.

For a right-pointing gate, use the following color-12 pixels in the combined 8×4 source–destination area:

(2,1), (3,1), (4,1), (5,1), (4,0), (4,2)

This forms a shaft with a three-pixel arrowhead. Rotate this sprite for UP, DOWN, and LEFT.

The arrow is drawn over floor and under characters. Because it spans the boundary and two cells, part of it remains visible when a character occupies either endpoint.

Animation and causal feedback

A successful shepherd action triggers a deterministic four-subframe animation. These frames require no further action and consume no resource.

The shepherd sprite moves halfway, two rendered pixels, toward its destination.

The shepherd reaches its new cell. A color-10 directional arrow appears in the central gap at x=30…33, centered vertically.

The companion moves halfway toward its destination, or offsets one pixel toward its obstruction.

Both characters render in their settled positions. A companion obstruction flashes color 8.

For a blocked shepherd action:

The shepherd offsets one pixel toward the obstruction.

The obstruction flashes color 8.

The shepherd returns to its cell.

The settled state is unchanged.

The companion remains completely still and no central command arrow appears when the shepherd is blocked.

Animation subframes do not invoke step(), do not increment any counter, and cannot accept queued input.

When the companion reaches its pen:

the pen perimeter fills inward with color 14 over six render-only frames;

the companion remains visible above it;

won is already true at the settled fourth movement frame.

Player-facing discovery

Both enclosures are identical open rooms. The characters begin at matching coordinates, and the pen is visibly to the right of the companion.

Level 2 — Useful Wall
Player-facing discovery

The companion begins against its enclosure’s upper wall. The shepherd begins in a hook-shaped passage where the direction toward the pen is not initially available.

Two low-cost observations distinguish the full collision rule:

Trying RIGHT immediately causes the shepherd’s wall to flash. The companion does not move even though its own right side is open.

Trying UP moves the shepherd, transmits the command, and causes the companion to bump its upper wall while remaining in place.

The player therefore sees that shepherd legality determines whether a command exists, while companion legality determines only whether the companion obeys that transmitted command.

The later downward moves prove that vertical commands are not generally ignored; the first UP failed specifically because of the companion’s local wall.

Level 4 — Borrowed Directions
Player-facing discovery

There are no gates and no new object types. The challenge is a stronger use of asymmetric blocking.

The companion begins on a route that appears to descend toward the bottom-left pen. Its wall at (5,2) prevents that direct descent, but the same obstruction lets the shepherd continue downward alone. That divergence is useful: it moves the shepherd into a lower command loop while preserving the companion’s position.

Later, different walls hold the companion from the right, left, and top. The player must repeatedly ask two questions:

Which direction should the companion eventually receive?

Where must the shepherd stand so that this direction can actually be issued?

The shepherd revisits (4,4), (6,2), and the right-hand chamber with different companion positions. A location that was useful earlier may provide the wrong command access later.

The level is not equivalent to following the companion’s shortest physical route.

Two especially important authored obstructions are:

Companion wall (5,2): opening it reduces the paired solution from 27 moves to the trivial five-command word LDDDD.

The central wall masses therefore do not decorate the map. They determine which command sequences the shepherd can generate and which commands the companion absorbs.

The solution revisits several junctions in different pair states, so the board cannot be replaced by a single corridor or a list of stations.

Level 5 — The Command Mill
Player-facing discovery

The shepherd now has a right-side shaft leading through an upward gate into the top passage. Once it crosses, it cannot immediately descend through the same edge. It must circulate across the top and down the left side.

That forced circulation produces long runs of commands. The companion’s pillars absorb some of them and accept others. The player learns to synthesize useful repeated directions by moving the shepherd around a loop:

a run may move both characters;

the same run at another companion position may move only the shepherd;

a gate may be dangerous on the shepherd side but useful as a brake on the companion side.

The left-pointing companion gate between (4,6) and (4,5) prevents a rightward crossing from (4,5). At step 18, this lets the shepherd reach the far-right cell while the companion remains one cell left.

Context-dependent roles

The shepherd reaches (6,2) four times:

after step 12, the companion is also at (6,2);

after step 24, the companion is at (4,2);

after step 38, the companion is at (5,6);

after step 46, the companion has reached the pen.

The same shepherd position therefore has four different meanings. Position alone is not a checklist item; the relevant state is the visible pair.

The gates also have contrasting roles:

The shepherd gate removes an easy reversal and forces a command-producing circuit.

The companion gate deliberately absorbs a right command and creates alignment.

Anti-degeneracy and necessity

Removing the shepherd gate reduces the shortest solution from 46 moves to 16.
Removing the companion gate reduces it to 20.

The depth is therefore not caused by long hallways. It comes from the interaction between:

shepherd circulation;

companion holding surfaces;

two differently situated copies of the same one-way rule.

Level 6 — The Long Way Above
Player-facing discovery

The companion starts only two cells below its pen. The obvious command is UP, but a downward-pointing gate lies immediately above it. From the companion’s side, UP would be a reverse crossing and is blocked.

This creates an unusually clear late-game impasse: the pen is visibly close, but the direct route cannot work. The companion must travel around the courtyard and approach the pen from above.

The first two UP commands are nevertheless useful. They hold the companion beneath the gate while moving the shepherd to the upper part of its double-loop enclosure.

A separate upward shepherd gate is crossed much later, only after the companion has been parked at the upper-right corner. Crossing it too early changes which circulation routes remain available.

The same gate rule therefore has two opposite strategic meanings:

the companion gate initially creates the problem but also provides a free holding surface;

the shepherd gate is a commitment that must be delayed.

Level 7 — Braided Escort
Player-facing discovery

The final level introduces no new noun or exception. It composes everything already demonstrated:

walls that hold the companion;

shepherd walls that remove commands;

loops that generate repeated directions;

shepherd gates that restrict circulation;

a companion gate that absorbs transmitted commands.

Two gates divide the shepherd’s upper route:

an upward gate on the left;

a rightward gate across the top.

Both must be crossed twice by returning through alternate parts of the courtyard. The gate rule has not changed; only the route context has.

The companion’s left-pointing gate prevents movement from (4,4) to (4,5). It absorbs four rightward commands over the solution. The most important composition occurs at step 53:

the shepherd uses RIGHT to cross its own top gate;

the companion receives the same RIGHT;

the companion’s opposite-facing gate absorbs it.

One command therefore commits the shepherd while deliberately preserving the companion. That is the game’s central idea in its strongest form.

Removing the shepherd’s rightward gate reduces the shortest path to 24 moves.
Removing the shepherd’s upward gate reduces it to 39 moves.

Removing the companion gate does not merely eliminate an obstacle: it removes the four useful rightward holds and changes the optimal depth to 60. This gate is a resource rather than a conventional lock.

The final board forms a dependency network rather than a chain:

either shepherd gate may be reached from multiple phases;

the companion gate is useful only at particular pair states;

several shepherd junctions are revisited with different companion positions;

locally correct companion movement can destroy the alignment needed for later commands.

Progression and systemic-role audit
Foundational attribution

Levels 1–3 each expose one causal distinction with immediate feedback:

Level	Intended rule	Plausible mistaken rule ruled out
1	Successful shepherd movement transmits the same direction	The two characters are independently controlled
2	Shepherd and companion collisions resolve separately	Either collision stops both; vertical commands are ignored
3	Gate legality depends on crossing direction	Gate is a wall, ordinary floor, decoration, or one-use device

No decoys, tight limits, hidden states, or irrelevant objects appear in these levels.
